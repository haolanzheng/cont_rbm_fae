# Experiment and source-code index

Run commands from the repository root. `python run.py list --all` lists available
entry points; an entry named `NAME` is invoked as `python run.py NAME`.
Datasets, checkpoints, results, and figures are excluded from the Git repository.
A report command requires the corresponding experiment outputs to be available
locally.

latent-space greedy search is not implemented.

## Data and output conventions

Use a distinct directory under `runs/` for each new experiment. Some historical
drivers return immediately when a completed result file already exists. To
recompute an experiment, preserve the old output separately and use a fresh
output directory where the driver supports one.

Several diagnostics require trajectory arrays or high-fidelity test solutions,
not just summary JSON files. These artifacts must be generated by the relevant
experiment or supplied separately. Historical reports describe the runs that
produced their inputs; they do not establish that a fresh checkout contains
those inputs.

## BGK dependencies and execution order

The project entry point compiles the C++ kernel when a BGK command requires it.
The compilation command is also available as `python run.py build-bgk`.

For a new run:

1. Preserve any existing `examples/bgk/decisive_output/` and
   `examples/bgk/temporal_output/` results.
2. Run `python run.py bgk_decisive init --workers 6`, followed by
   `python run.py bgk_decisive precision` and
   `python run.py bgk_decisive run --workers 6`.
3. Run `python run.py bgk_frozen_controls`, `python run.py bgk_precision_replay`,
   `python run.py validate_decisive`, and `python run.py summarize_decisive` as
   required by the comparison.
4. For temporal studies, run `python run.py bgk_temporal init`, then
   `python run.py bgk_temporal run --names old_pool old_adam new_pool new_adam --workers 4`.
5. For the reordered trajectory, run
   `python run.py bgk_temporal run --names old_adam_swapped --workers 1`, followed
   by the relevant branch, endpoint-refinement, validation, and report commands.

Precision replay requires the original trajectory data, including
`mechanism_output/trajectory_snapshots.npz`; the file is not distributed with
the source code. Preserve local copies if historical replay is needed.

## Thermal-fin example

```bash
python run.py fin_local_study --task validate --d 11 --out fin_d11
python run.py fin_local_study --task test --d 11 --out fin_d11
python run.py fin_local_study --task run --d 11 --rank 50 --method adam100 --seed 11 --out fin_d11
```

Batch experiments also require the corresponding test caches for `d=21` and
`d=33`. The batch driver reports missing prerequisites rather than waiting
indefinitely. See `examples/thermal_fin/README.md` for the model and search
settings.

## Historical limitations

The presence of a related model does not establish that every historical result
can be reproduced by the current drivers. In particular, the dedicated
thermal-fin continuation and paired-comparison driver for ranks 40 to 50 was not
recovered. The defaults in `local_separation_theory.py` also differ from some
later experiments. Check the configuration and required inputs before comparing
new results with an archived run.
